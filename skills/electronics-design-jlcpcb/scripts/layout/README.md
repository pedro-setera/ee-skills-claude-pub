# Layout helpers

Building blocks for a project's own board script, `src/build_board.py`. They were ported from the tools of one
board and tested lightly: every result is a **first pass**. The rules, checks and reviews of the skill do not depend
on them. Run the checks on the saved board and look at the render after every build.

| File | What it gives |
|---|---|
| `board.py` | a KiCad board from the netlist and `mech/outline.json`: outline, holes with keep-outs, free bands, layer count, footprints, net classes, layer stack |
| `place.py` | fixed parts, blocks around an anchor, a packer for the small parts with reserved areas, label room, a placement plot |
| `copper.py` | hand-planned copper from a table: zones, tracks, vias, keep-out areas, stitching vias |
| `route.py` | a grid router for the nets that are left (simple and medium boards only: see "Where the router stops") |
| `repair.py` | closes what the router left open, ties ground islands, removes dangling vias and track ends; keeps a change only when the board is no worse |
| `fill.py` | zone fill in a process of its own, then a check of the saved file against a fresh fill |

`board`, `place`, `copper` and `route` are libraries and need KiCad's Python: the project script calls
`kicad_io.need_kicad_python()` first. `fill.py` and `repair.py` are also command-line tools
(`python -I scripts/layout/fill.py --help`); they need `--in-place` to change a board and otherwise work on a copy.
All coordinates are KiCad's own: millimetres, x to the right, y downwards.

**No window, ever.** In KiCad's Python every message of KiCad's log becomes a message box that blocks the script.
The helpers send the log to stderr before their first pcbnew call. A script of your own that calls pcbnew
directly calls `layout.quiet_wx()` first. Give every child process a time limit.

## When to use them, and when not

Use them when the board is generated by a script anyway (a new design made with this skill), is simple or medium
(two or four layers, up to about 150 parts, no ball-grid package), and you want a board that can be built again
after every schematic change.

Do not use the router for:

- **Length matching, differential pairs, controlled impedance.** A USB pair, a clock that must match, a radio
  line, a memory bus: drawn by hand (`copper.py`) from their own rules, before the router runs.
- **Ball-grid and fine-pitch escape.** It cannot pass a track between pads closer than about 0.55 mm edge to
  edge. Escape such pins by hand; the router continues from the stubs.
- **Fast or sensitive nets** (rule GEN-19: unbroken ground under every fast or sensitive net). The router does
  not know that rule. It will change layers and cross a gap in the ground when that is shorter. Route these nets
  by hand first, keep their layer below free with a keep-out area, and prove the result with
  `scripts/return_path_check.py`.
- **Dense boards** (more than about 60 percent of the area used) and boards beyond about 150 parts: it leaves
  nets open (reported, never hidden) and takes minutes.

Do not use the helpers to change a design that somebody else drew: `fill.py --check` and `repair.py` without
`--in-place` read such a board and work on copies; everything else is for boards the script owns.

## How a project script uses them

1. `B.load_mech(...)`, `B.new_board(netlist, mech, ...)`: the board with every part parked beside it.
2. `P.Placer`: `fixed()` for everything that mechanics decide, `block()` for each circuit block as its datasheet
   draws it, `reserve()` for every area that hand copper needs, `pack()` for the rest, critical parts first.
   Look at `placement.png` before going on.
3. `C.apply(board, plan)`: the copper that decides whether the board works. Pours, the hot loop of a converter,
   escapes of fine pins, feeds, keep-outs.
4. `R.Router`: `keep_spokes()` and `fanout()` for every poured net, `make_plan()`, `route_all()`, `fanout()`
   again, `C.stitch()`, `commit()`.
5. `B.save()` with the rules, net classes and rule file; `fill.fill()`; `repair.repair()`.
6. `scripts/drc_run.py --project ...`, the other checks, and the render. Open the images.

The script below is the tested example (`example_node`: a USB-C input, a regulator, a sensor, a header; 20
parts on 30 x 20 mm, two layers). Copy it into the project's `src/` folder and replace the tables.

```python
"""Build the board of the example node from its netlist: place, plan the copper, route, fill.

usage: python -I src/build_board.py <the skill's scripts folder> <board folder>
The board folder holds kicad/ (the schematic project) and out/netlist.net. Writes kicad/example_node.kicad_pcb
with its project and rule file, out/layout/placement.png, placement.json and route.log. Exit 0: built and the
saved fill checked; 1: something is unplaced, unrouted or stale; 2: could not run.
"""
import json
import os
import sys

SCRIPTS, PROJECT = sys.argv[1], sys.argv[2]
sys.path.insert(0, SCRIPTS)
import kicad_io                                    # noqa: E402

kicad_io.need_kicad_python()                       # from here on: KiCad's own Python
from layout import board as B, copper as C, fill, place as P, repair, route as R      # noqa: E402

NAME = "example_node"
KICAD, OUT = os.path.join(PROJECT, "kicad"), os.path.join(PROJECT, "out", "layout")
PCB = os.path.join(KICAD, NAME + ".kicad_pcb")

# ---- the mechanical input (in a project: mech/outline.json, written in the board definition) --------------------------
MECH = {"outline": {"rect": [100, 100, 130, 120], "corner_radius": 1.0},
        "holes": [{"name": "H1", "x": 113.0, "y": 115.6, "d": 2.2, "keepout_d": 4.6}],
        "keepouts": [{"kind": "band", "name": "upper slot", "edge": "top", "width": 1.5},
                     {"kind": "band", "name": "lower slot", "edge": "bottom", "width": 1.5}]}
RULES = dict(B.RULES)                              # the minimums of the day, from the manufacturer's live page
CLASSES = {"POWER": {"nets": ["VBUS", "+5V", "+3V3"], "track": 0.4, "track_min": 0.2}}


def main() -> int:
    os.makedirs(OUT, exist_ok=True)
    mech = B.load_mech(MECH)
    brd = B.new_board(os.path.join(PROJECT, "out", "netlist.net"), mech, layers=2, rules=RULES, kicad_dir=KICAD)

    # ---- placement: fixed mechanical parts, the regulator's block, then the rest by the packer ----------------
    p = P.Placer(brd, mech)
    p.fixed({"J1": (103.4, 110.0, 270),            # USB-C: its "PCB edge" line on the left board edge
             "J2": (127.6, 104.9, 0),              # header at the right edge, pin 1 up
             "TP1": (116.4, 102.8, 0),             # the 3.3 V test point, by hand (the packer found room for
             "U1": (118.0, 107.0, 0),              # it only 15 mm from its net)
             "U2": (120.6, 111.0, 0),
             "R3": (108.9, 115.0, 270),            # the shell's resistor beside the lower shell tab
             "TP2": (106.1, 117.15, 0)})           # the ground test point, by hand: 1 mm clear of the connector's
                                                   # courtyard (testpoint_check.py; the packer left 0.9 mm) and its
                                                   # own courtyard still outside the lower free band
    p.block("U1", {"C1": (-4.0, -0.95, 180),       # input capacitor at VIN, output capacitor at VOUT,
                   "C2": (3.9, -0.95, 0),          # the enable pull-up beside EN
                   "R4": (-3.8, 1.0, 0)})
    p.block(("J1", "A5"), {"R1": (3.7, -0.4, 0), "R2": (3.7, 1.4, 0)})      # CC pull-downs at the CC pads
    p.block("U2", {"C4": (2.3, 0.0, 90)})          # the sensor's capacitor across its supply pads
    p.reserve((107.2, 107.0, 108.9, 113.0), "USB-C pad escapes")
    p.pack([("F1", "J1", "B9", "1", 6), ("D1", "F1", "2", "1", 4), ("C3", "C2", "1", "1", 4),
            ("R5", "J2", "2", "2", 4), ("R6", "J2", "3", "2", 4), ("R7", "J2", "5", "1", 6),
            ("D2", "R7", "2", "2", 4)])
    rep = p.finish()
    p.plot(os.path.join(OUT, "placement.png"))
    with open(os.path.join(OUT, "placement.json"), "w", encoding="utf-8") as f:
        json.dump(rep, f, indent=1)
    print(f"placed {len(rep['placed'])}; failed {rep['failed']}; unplaced {rep['unplaced']}; without a label "
          f"{rep['unlabelled']}; overlaps {rep['courtyards_overlap']}")
    if not rep["ok"]:
        return 1

    # ---- planned copper, from pad positions (no coordinate is typed twice): the escapes of the sensor's fine
    #      pads (its footprint keeps the copper under the body free); the link between the connector's two VBUS
    #      pads on the bottom layer, so that the two CC lines between them leave straight on top (left to the
    #      router, that link ran under the connector's shell or cost each CC line two vias); then ground fills
    #      on both layers -------------------------------------------------------------------------------------
    def out(ref, pin, dx):                         # a short stub straight out of a pad
        x, y = p.pad_xy(ref, pin)
        return [(x, y), (x + dx, y)]

    def to_pad(a, b):                              # out of pad a along x, then a 45 degree leg into pad b
        d = abs(b[1] - a[1])
        return [a, (b[0] - d if b[0] > a[0] else b[0] + d, a[1]), b]
    vb, va = out("J1", "B9", 1.4), out("J1", "A9", 1.4)
    C.apply(brd, {
        "tracks": [{"net": "SDA", "layer": "F.Cu", "width": 0.2, "points": out("U2", "1", -0.9)},
                   {"net": "SCL", "layer": "F.Cu", "width": 0.2, "points": out("U2", "2", -0.9)},
                   {"net": "+3V3", "layer": "F.Cu", "width": 0.2,
                    "points": to_pad(p.pad_xy("U2", "3"), p.pad_xy("C4", "1"))},
                   {"net": "GND", "layer": "F.Cu", "width": 0.2,
                    "points": to_pad(p.pad_xy("U2", "4"), p.pad_xy("C4", "2"))},
                   {"net": "VBUS", "layer": "F.Cu", "width": 0.4, "points": vb},
                   {"net": "VBUS", "layer": "F.Cu", "width": 0.4, "points": va},
                   {"net": "VBUS", "layer": "B.Cu", "width": 0.4, "points": [vb[1], va[1]]}],
        "vias": [{"net": "VBUS", "at": vb[1]}, {"net": "VBUS", "at": va[1]}],
        "zones": [{"net": "GND", "layer": "F.Cu"}, {"net": "GND", "layer": "B.Cu"}]})

    # ---- routing: ground first (fan-out), power, then the rest, long before short -------------------------------
    log = open(os.path.join(OUT, "route.log"), "w", encoding="utf-8")

    def say(text):
        print(text)
        log.write(text + "\n")
    r = R.Router(brd, rules=RULES)
    r.keep_spokes("GND")
    hand = [("U2", "4")]                           # this ground pad has its hand-made track to C4's ground pad
    say(f"ground fan-out before routing; pads without a via: {r.fanout('GND', skip=hand) or 'none'}")
    plan = R.make_plan(r, classes=[{"nets": ["VBUS", "+5V", "+3V3"], "width": 0.4}], default={"width": 0.2},
                       long_span=15.0)
    left = R.route_all(r, plan, log=say)
    say(f"ground fan-out after routing; pads without a via: {r.fanout('GND', skip=hand) or 'none'}")
    say(f"stitching vias: {C.stitch(r, 'GND', pitch=4.0)}")
    say(f"written: {r.commit()} tracks and vias; open: {left or 'nothing'}")

    # ---- save with the project settings and the rule file, fill in a process of its own, check the saved file ----
    with open(os.path.join(SCRIPTS, "jlcpcb.kicad_dru"), encoding="utf-8") as f:
        template = f.read()
    dru = template[:template.index("# 8. EXAMPLES")] + "# 8. Net classes of this board\n\n" + B.class_rules(CLASSES)
    B.save(brd, PCB, rules=RULES, netclasses=CLASSES, dru=dru)
    res = fill.fill(PCB)
    say(f"zone fill: {res['result']}")
    fixed = repair.repair(PCB, tie=["GND"], out=OUT)
    say(f"repair: {fixed['result']}: {fixed['summary']}")
    log.close()
    return 0 if not left and res["result"] == "PASS" and fixed["result"] == "PASS" else 1


if __name__ == "__main__":
    sys.exit(kicad_io.run_main(lambda argv: main()))
```

## The mechanical input: `mech/outline.json`

Written in the board definition (phase 8), read by `board.load_mech()`. Millimetres, KiCad's frame (x right, y
down, seen from the top side).

| Key | Meaning |
|---|---|
| `outline.rect` | `[x0, y0, x1, y1]`: a rectangular board; or |
| `outline.polygon` | `[[x, y], ...]`: the corner points in order (three or more) |
| `outline.corner_radius` | radius of every corner, a true arc on Edge.Cuts (default 0) |
| `holes[]` | mounting holes: `name` (reference on the board, default `H1`, `H2`, ...), `x`, `y`, `d` (drill), `keepout_d` (diameter kept free of parts, tracks and vias: from the screw head, the stand and the tool; without it only the hole itself is kept free, and that is reported), `plated` (default false), `pad_d` (pad diameter of a plated hole, default `d` + 1.6), `net` (net of a plated hole) |
| `keepouts[]` with `"kind": "band"` | the strip of a board edge that a slot or rail of the case holds (rule MECH-06): `name`, `width`, and either `edge` (`left`, `right`, `top`, `bottom` of the board's box, with an optional `span` `[a, b]` along that edge) or `line` `[x0, y0, x1, y1]` (the band lies on the side of the line toward the board's centre). The same keys that the board checks read (`sides`, `copper_to_edge`, `allow_exposed_copper` are theirs; here a band is kept free of parts, pads and copper on both sides, the conservative reading) |
| `keepouts[]` with `"kind": "area"` | any other keep-out: `name`, `rect` `[x0, y0, x1, y1]` or `polygon`, `no` (a list of `parts`, `tracks`, `vias`, `pour`; default all four), `layers` (copper layer names; default all) |

Bands may also stand in `board.toml` as `[[keepout.band]]` with the same keys; when `board.toml` has any, those
are used and the bands of the JSON file are not. Bands, hole keep-outs and areas become rule areas of the KiCad
board; the placer and the router read the board's rule areas, also those inside footprints.

## Lessons on route order and escapes

They come from routing a medium board with these tools many times.

- **Room first.** A board that is too dense for its outline cannot be routed by any order. Give every block
  room and leave one wide channel for the nets that cross the board. Most lost time was congestion at a neck.
- **Route order matters more than anything else.** Power pours and wide nets first; then the few nets that must
  cross the board before others close their way (name them as the first class of `make_plan`); then the long
  nets, longest first, on the far side (`long_span`, `long_layer_cost`); then the short ones. Long before short
  left far fewer open connections than the reverse.
- **Escapes by hand, before routing.** Fine-pitch pins get a short stub or a via each in `copper.py`; pins of a
  connector row get nested lanes that end on the pads of their series resistors. The router continues from the
  stubs. Escape vias that end up unused are removed by `repair.py`.
- **A feed gets its own planned path.** A wide feed laid by the router closed the last millimetre of a long net.
  Drawn by hand away from that net, or kept away with `avoid=`, it never did again.
- **Ground.** A fan-out via for every ground pad before anything else is routed (`fanout`), a ring around every
  through-hole ground pin so that the spokes can form (`keep_spokes`), stitching after routing (`stitch`),
  islands tied by `repair.py --tie GND`. Two long tracks side by side along an edge enclose an island that no
  via can reach: do not let them run parallel with parts behind them.
- **Keep-outs say what is forbidden.** No signal on the far side under a converter's input loop, its switch
  node, its inductor and its output capacitors (vias allowed); a keep-out on the part's own side between the
  inductor's pads. Trim keep-outs to what the rule needs: too large, they close the board.
- **The packer is for passives.** Fix by hand every part that forms an escape corridor, and keep `reserve()` up
  to date with every hand track, or the packer drops a part on it. It is greedy: a part that finds no room near
  its anchor is placed up to three times as far away and reported; read the report.
- **Look after every build.** The placement plot and the copper plots of every area. A routed, rule-clean board
  proves only that it is connected.

## Where the router stops

- A 0.1 mm grid; tracks at 0, 45 and 90 degrees; through vias only; no arcs, no teardrops, no via in a pad, no
  neck-down at a pad.
- It knows widths and clearances, not currents, return paths or noise. It will run a track under a switching
  node or cut a ground fill if nothing forbids it.
- Inner layers are taken as planes; tracks go on the outer layers unless `route_layers` says otherwise.
- A net that has a zone is not routed: its pads are joined by the pour (`fanout` gives each surface-mount pad
  its via). A pad that finds no room for its via is named; give it a hand track to a place with room.
- What a reviewer will see in its work: a track ends on the 0.1 mm grid inside a pad or on a track, not at the
  centre; a short jog where it passed an obstacle; a hand-made stub whose tail it did not use (`repair.py` cuts
  it back); two vias and a jumper on the far side where an earlier net closed the direct way (change the order
  or plan that net by hand).

## Checks after a build

`fill.py` ends with its own check (the saved fill against a fresh fill, and its distance to the board edge).
KiCad's rule check cannot replace it. `kicad-cli pcb drc` judges the fill as it is saved: it does not fill by
itself, in KiCad 9 and in KiCad 10 (KiCad 10 has `--refill-zones`, which `drc_run.py` does not use). KiCad 9's
rule check also does not report a saved fill that lies too near the board edge; KiCad 10's does. So fill and
save before every rule check, and after every change of a rule. KiCad fills by an `edge_clearance` rule of the
custom rule file where there is one, also when the board setup asks for more: keep the two equal.

## KiCad 10

Proven on KiCad 9.0.8; the tests also pass on KiCad 10.0.8. What differs there and is handled inside the
helpers: the call for the board outline, the footprint flags, the copy of an item, and the project file of a new
board (KiCad 10 writes none with the first save: `board.save()` loads the board and saves it again). What you
must know yourself: KiCad 10's stock libraries rename pads (the shell pads of the USB-C receptacles are `SH`,
in KiCad 9 `S1`), so a schematic made for one version may not fit the footprints of the other; `new_board()`
names every symbol pin without a pad and builds nothing. And KiCad 10's `SaveBoard` gives a via or track that
is joined to no pad and lies in the saved fill of another net the net of that fill: lay copper before the first
fill, as the example does, or on a board whose fill is fresh.

Results: `fill_check.md` / `.json`, `repair.md` / `.json` in the results folder; the placement report and plot
are written by the project script. Exit codes of the two tools: 0 pass, 1 findings, 2 could not run.
