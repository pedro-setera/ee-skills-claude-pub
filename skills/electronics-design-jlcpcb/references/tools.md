# Tools: what the skill uses, how to find them, what to do without them

Run `python -I scripts/env_check.py` at the start of every session. It prints this table for the machine it runs on. Ask the user before installing anything; name the tool, the version and where it comes from.

## 1. The tool matrix

| Tool | Used for | Without it |
|---|---|---|
| KiCad, latest stable (its command line `kicad-cli` and its own Python with `pcbnew`) | Schematic and board files, ERC, DRC, netlist, Gerbers, drill, 3D export, renders | Stop after phase 4. The design exists on paper only; say so |
| KiCad's readers for other tools' files (Altium, Eagle, EasyEDA and others; `scripts/import_design.py --list` shows what this version reads) | Bringing an existing design from another tool into KiCad for review | Review from exports only (PDF, netlist, BOM, Gerbers); say what that cannot verify (`references/existing-designs.md`) |
| ngspice (shipped with KiCad) | Simulation campaign | Affected points are UNKNOWN; they go to the bench list and gate 1 says so |
| LTspice | Only when a part's model exists for it alone | Use a behavioural model from the datasheet and mark it as such |
| Python 3.11 or newer | All scripts | Stop: nothing can be checked |
| numpy, matplotlib, Pillow | Geometry checks, plots, image tiles | The check that needs it reports FAIL "cannot run"; ask to install |
| SciPy (optional) | RF filters: the standard prototypes (Butterworth, Chebyshev, elliptic) and optimisation | Butterworth and Chebyshev values from their closed forms in plain numpy; an elliptic filter waits for the install. Ask to install |
| scikit-rf (optional) | RF filters and matching: reading the makers' Touchstone (S-parameter) files, cascading them, plots | A small Touchstone reader and cascade in the project's own script (numpy). Ask to install |
| CadQuery (optional) | `body_check.py`: 3D bodies against holes and courtyards | The check reports FAIL "cannot run"; the mechanical and visual reviews carry the item with zoomed renders of every hole |
| easyeda2kicad (optional) | JLCPCB library footprints and 3D models for `jlc_rotations.py` and `fetch_parts.py` | Rotations cannot be derived: mark every polarised part UNKNOWN and check each in JLCPCB's placement preview and at the placement confirmation |
| poppler `pdftoppm` (optional) | PDF pages to PNG | Use KiCad's own image export |
| curl | Downloads by direct URL | Any HTTP client that takes a direct URL |
| Browser extension with the user's signed-in session (Claude in Chrome) | JLCPCB and LCSC pages, file upload, placement viewer, order page | Prepare the upload folder and a click-by-click list; the user clicks |
| Push notification | Order status changes | Report at the next check in the conversation; say that no push is available |
| Scheduled tasks | The 4-hour order check, the hourly mail check | Check only when the user asks; say that the watch is not running |
| Mailbox access (connector or the user's webmail in the browser) | Manufacturer e-mails | The user forwards the mails |
| Sub-agents | Independent reviews, parallel work | Run each review in a fresh session, one at a time; never review in the designer's context |

## 2. Asking for an install

```
<tool> <version> is missing. It is needed for <what>.
Suggested: install it from <official source>.
Why: <one line>. Without it: <what will not run>.
```

Install only what the user approved, from the maker's official source. After the install, run `env_check.py` again and record the versions in the state file.

## 3. Working without a tool

- Never pretend a check ran. A check that cannot run is FAIL with the reason, and the gate summary lists it.
- Move what cannot be verified by tool to the nearest stronger step: a missing geometric check goes to the visual review with named zoom images; a missing simulation becomes an UNKNOWN with a numbered bench test and a numeric pass value. These UNKNOWNs are listed in the gate summary for the user to accept; you do not settle them yourself.
- Tell the user once, plainly, what is not running and what that costs in confidence.

**The layout helpers** (`scripts/layout/`; manual with a tested example: `scripts/layout/README.md`) serve a board that a project script generates: two or four layers, up to about 150 parts, no ball-grid package. Every result is a first pass: run `scripts/drc_run.py` and the other checks, and look at the render, after every build. The router gets no fast or sensitive net, no pair, no length-matched or impedance-controlled line and no fine-pitch escape (phase 9, step 10). `new_board()` stops when a footprint is missing or a symbol pin has no pad. `fill.py` and `repair.py` change a board only with `--in-place`; otherwise they work on a copy. A project script that calls KiCad's Python itself calls `layout.quiet_wx()` before its first board call, so that no message window can open on the user's screen.

**The panel script:** `python -I scripts/panel.py --project <board folder>`, settings in the table `[panel]` of `board.toml`; results in `out/panel/`, the panel as a KiCad project of its own in `out/panel/board/`. It refuses a bridge nearer than `part_clear_mm` to a fitted part (default 2.0 mm, `references/pcb-rules/dfm-dft.md` DFM-31), a bridge on a curved edge, a board without a bridge, and a bridge on an edge that a slot or rail of the case guides, unless `nubs_removed_flush = true` records the decision to remove the nubs flush (DFM-31); it draws no tooling holes (the order form then says "Tooling holes: Added by JLCPCB"), and with `tooling_d_mm` it accepts only JLCPCB's own size unless the project says the panel is not for JLCPCB (`references/pcb-rules/dfm-dft.md` DFM-20). Its default sizes are common values that passed the supplier's review, not published supplier figures: read the live pages. The silkscreen keeps the board's designators; the panel's files carry `<ref>_<n>`. The board's own checks run on the single board. Its package and Gerbers: `python -I scripts/fab_package.py --project <board folder> --out out/panel --name <name>-panel --bom out/panel/<name>-panel-bom.csv out/panel/board/<name>-panel.kicad_pcb` (into `out/panel/jlc/`, where `edge_check.py --project` measures them).

The rules, checks and reviews of the skill do not depend on the helper scripts. If a helper does not fit a board, write the board's own generation code in the project's `src/` folder and keep the checks.

Every script: `python -I scripts/<name>.py --help`; exit code 0 only on pass, 1 on findings, 2 when it could not run (exceptions: `status_diff.py` exits 1 when an order's main status changed, `env_check.py` when an optional tool is missing); a Markdown result and a JSON result. Call it with `--project <board folder>` (it reads `board.toml` there and writes its result under `<board folder>/out/` with a fixed name), or with explicit inputs and `--out <folder>`. `scripts/check_all.py` runs the whole check suite and writes the one-page `out/CHECKS.md`.

`python -I` hides the user's own Python packages. A script that needs numpy, matplotlib or Pillow calls `kicad_io.add_user_site()` before importing them; a project's own script in `src/` does the same.

**What each board check proves, and what it cannot.**
- `kicad_io.py` (`run_cli`, `run_guarded`, `quiet_wx`): no KiCad process that the scripts start can put a window on the screen or wait for a click, and none outlives its time limit; a child that could not start is "could not run", never a result. It cannot protect a KiCad the user starts by hand, or code that imports KiCad's Python without calling `quiet_wx()` first.
- `drc_run.py`: the saved board meets KiCad's rules and the rule file (proven loaded by a rule that must fire on a copy), nothing is unconnected, and the board matches the schematic. It cannot prove that a custom rule's condition is right (a mistyped condition never fires), that the fill is up to date, that the Gerbers equal the board, or that the board works: a clean result says the board is connected and can be made.
- `netlist_check.py`: the exported netlist against the hand-written intent file: every listed connection is there, nothing listed as separate is joined, the pins are the named ones. It cannot be better than the intent file: a connection that nobody listed is not checked, which is why the file is written independently, from the datasheets.
- `netlist_check.py --screens`: four screens that need no intent file, for a design the user brought (a two-pin part shorted out, a supply pin fed only through capacitors, a rail fed only through an open or unfitted link, a pin alone on its net); result `netlist_screens.md`; leads for the reviewer, not verdicts. Waivers with a written reason in `src/netlist_screens_waivers.toml` (`board.toml [netlist_check] screen_waivers`); ground net names in `[netlist_check] screen_ground`. Supply pins are known only by their pin type `power_in`: a library that types them passive is listed as not checked, not screened. Connectors are known by prefix (J, P, X, CN, CON) or a Conn/Connector name; an edge connector named otherwise whose supply pins are typed power input gives a lead on its rail. Links are taken to conduct both ways; transistors and chips are never walked through, so a rail behind a load switch counts as fed. Ground is known by net name only. It does not judge values, ratings or whether the intent is right.
- `check_all.py`: one run, one board checksum, one page; a check that did not run is a CANNOT RUN row, counted apart from failed and never as a pass, and the headline says what it needs (`NOT PASSED: 4 passed, 4 failed, 12 could not run, 3 not applicable`). It cannot say whether a limit in `board.toml` is right, and it does not do the looking. Run `fab_package.py` and `interface_export.py` first.
- `jlc_rotations.py`: each placed part fits JLCPCB's cached footprint pin for pin within its package limit, with enough anchors and no rival turn; a two-pin part with a polarised footprint by the polarity mark read in both footprints, UNKNOWN when a mark is missing or the marks disagree; its test proves consistency with the derivation. It cannot prove the cached footprint equals JLCPCB's production library or that our pad 1 is the marked terminal when the footprint's own mark agrees with it: the placement preview does. Without `--project` or `--vendor` it has no footprint folder: every part UNKNOWN.
- `fab_package.py --check`: the package's files and every input that made them (board, `board.toml`, BOM table, footprints, tools, KiCad version) are unchanged. It is not a release gate.
- `silk_check.py`: text sizes, clearances measured on each text's box (the strict reading), each label beside its own part, every part labelled or waived in writing. It cannot see a label hidden under a body larger than the footprint drawing, nor check polarity marks, pin legends or what a text means.
- `edge_check.py`: copper to the edge, measured on the exported Gerbers of board and panel (the panel's in `out/panel/jlc/gerbers/` whenever the project has a panel; missing there: CANNOT RUN), with a larger limit along edge bands. It cannot check holes, mask or silkscreen to the edge, or negative plane layers (reported UNKNOWN). Run it again after every export.
- `neck_check.py`: resistance, drop, loss and an upper bound of the rise for each power path the designer names, with the narrowest copper found in tracks and pours. An estimate on an IPC-2152 basis, not a verified ampacity; without a named path the result is UNKNOWN; for pulses of a second or more its via bound is very conservative; anything UNKNOWN goes on the bench list.
- `zone_check.py`: ground islands and their ties, webs between hole clearances, vias near named pads, fence count, stitching distance, single-point islands, on the saved fill. It cannot tell whether the fill is up to date (fill and save first), nor the return path of any one signal (`return_path_check.py`). On a 2-layer board the web check is UNKNOWN until `planes` names the ground side.
- `body_check.py`: 3D bodies inside their courtyards, nothing in a mounting hole's keep-out, mated plugs clear, edge bands free. It needs CadQuery: without it CANNOT RUN, and the visual review carries the item. It cannot check bodies against each other or against the enclosure, nor a 3D model that is itself wrong; parts marked "do not populate" are NOT CHECKED; a board that names 3D models KiCad cannot find has no bodies to check.
- `fp_audit.py`: the numbers of every footprint for the comparison with the maker's drawing, and flags (courtyard smaller than pads or body, model missing or outside the courtyard, silkscreen over pads). It cannot know the right pitch or land pattern: compare its table by hand with the drawing open.
- `review_images.py`: the same image set every time, at a scale where every designator is readable, every crop named, edge bands drawn. It does not look: open the images and write what you saw, with the crop names.
- `interface_export.py`: outline, holes, connectors and heights in one generated file with the checksums of board and STEP; `--check` shows a stale file at once. It cannot check the enclosure; heights need CadQuery and 3D models that exist.
- `import_design.py`: brings another tool's board into KiCad on a copy, records everything the importer said, and verifies the import against exports of the original tool (netlist, BOM, drill, Gerbers). Until that passes, every finding is "found on the import; confirm in the original". It cannot import a schematic by command (it prints the clicks) or measure what the importer lost (fonts, custom pads, 3D models, rules).

- `pin_function_check.py`: for every programmable part (`programmable = true` in its block of `src/datasheet_pins.toml`), what the design uses each pin for (`src/pin_use.toml`) against what the maker's table offers on that pin (`functions` and the limits): a connected pin without a use, a function the pin does not have, two jobs on one pin, one single function on two pins, an output on an input-only pin, an analogue use on a pin without it, a pin sampled at reset or belonging to the debug port or the oscillator used for something else without a written reason. Where the table declares them it also fails a direction against the function's mode (`function_modes`, with its source), two uses of one shared resource at different settings (`resources`, `setting`) and a peripheral whose pins mix two pin sets (`pin_sets`). Every chip (U or IC, 8 pins or more, settable) needs `programmable = true` or `false` in its block: one without is UNKNOWN, and NOT APPLICABLE comes only when every chip is classified and none is programmable. Result `out/pin_function_check.md`. A PASS is per-pin table consistency: it trusts both tables as typed (a typing error passes), marks each pin whose direction was not checked, and does not check the clock tree, DMA, interrupt lines, IO bank voltages, functions that exclude each other beyond what the table declares, the level a reset-sampled pin needs, the state of pins in reset and during programming, 5 V tolerance or drive strength: the joint peripheral-allocation review (`references/reviews.md`).
- `ratings_check.py`: every pin number of the symbol against the hand-typed datasheet table, both ways; every pin name; the worst case of each net against each pin's recommended range (finding) and absolute limits, transients included (blocker); a rating relative to a pin on another net with the two nets independent unless `[tracks]` declares how one follows the other, an absolute one also with the other net off (UNKNOWN where the table does not say whether that state occurs); a nan or inf in the table is a finding; "leave open" pins; and, for every pin that carries the key `input`, what holds it while its driver is high-impedance. Every chip, transistor, diode, polarised capacitor and connector without a block, every pin without a rating and every net without a level is listed UNKNOWN. It cannot tell whether the table is typed correctly (a typing error passes; the schematic reviewer compares it with the datasheets), judge currents, power, timing, the value of a pull or the level of a divider, tell whether the relations of `[tracks]` and the off states typed are true, prove the order and timing of the supplies beyond those states (`references/pcb-rules/power.md` PWR-63), allow the current some datasheets permit into a pin beyond a relative rating, or say whether a pin listed as "driven by" is always active. A pin without the key `input` is not checked for its default level; a connector pin never counts as a driver; a net driven only by an open-drain or three-state output is judged by hand. An ESD pulse is not a level: judge it by `references/pcb-rules/protection-esd.md` ESD-02, ESD-03 and ESD-23.
- `testpoint_check.py`: on the saved board, for every test point (footprints with the prefix `TP`, and the pads named in `board.toml`) the pad size, open mask and no paste, spacing, distance to parts, to tall parts and to the edge, its label, a ground point within reach; that every net of the list `required` has a point; with `fixture = true` one side, the pitch, the edge distance and two unplated locating holes. It writes the one table `out/testpoints.md` and one overview image per side: open both. It cannot know which nets need a point without the list `required`, or whether a fixture is planned without the key `fixture` (both UNKNOWN, never a pass), judge a point on a crystal pin, an RF line or a high-impedance node (DFM-97), judge the reach with the board mounted, or fill in the normal values. It knows the height of a neighbour only from `body_check.py`'s result of the same board state or from the table `[heights]`: run it after `body_check.py`.

- `return_path_check.py`: for every net of the list `[fast_nets]`, whether copper of the reference nets lies under the whole width of every track, on the saved fill: each uncovered stretch with its length, its place and what lies below; the distance from each layer change to the nearest return via; one overlay picture per reference layer and a tile per finding (`out/review/return_path/`). It cannot know whether the list is complete (the reviewer makes an own list), nor whether the fill is up to date (fill and save first). It judges one reference layer per signal layer, not the second plane of an inner layer, a return through series parts, crosstalk or stubs. A supply plane counts as a reference only when `reference` names it. Its limits (0.2, 1.0 and 2.0 mm) are starting points for fast nets: set others per board and write why. A listed name that is not on the board is a finding. It reports each track's smallest distance to the edge of its reference copper but does not judge it: the margin of `references/pcb-rules/general.md` GEN-08 is the reviewer's. It does not look: open every picture and follow each net from end to end.
- `impedance_check.py`: the impedance that the widths, gaps and layers really on the board give, from the board's own layer stack: per net and layer the geometry found, the formula used, the result against target and tolerance; every stretch at another width; for a pair its gap, the share of its length that runs coupled, and the length difference. A second method beside the manufacturer's calculator, never instead of it: closed-form formulas, bare copper within about 4 % of a field solution in the tested cases, about 10 % on a real board. On an outer layer under solder mask it reads HIGH: about 1 to 5 % for a single line and 4 to 6 % for a pair, on top of the formulas' own 0 to 3.5 %. It cannot check the manufacturer's stack (compare the stack it prints with the stack-up page of the order), compute solder mask or etching, a pair with ground beside it, or a line without a plane below (UNKNOWN, never a pass). Where it and the manufacturer's calculator differ by more than the tolerance, stop and find out why.

**One KiCad version per project.** A file saved by a newer KiCad cannot go back to an older one. KiCad 9 and KiCad 10 fill zones slightly differently, write pin names differently into the netlist, and KiCad 10's rule check has one more parity test. After a change of version: fill and save again, export the netlist again, make every reference file again, and read each new warning. The version is written into the state file.

**Not provided in this version, for RF filters:** a reusable filter script (each project writes its own in `sim/`, as `references/simulation.md` describes) and an electromagnetic solver for filters and couplers drawn in copper, which are outside the proven range. Graphical RF design programs are not used: an agent cannot drive them repeatably, and the user is not asked to design in them.

**Not provided in this version, for fast and dense boards:** a field solver or a stack-up calculator (`impedance_check.py` is a closed-form second method beside the manufacturer's calculator), a check of length matching across a bus (only the two lines of a pair are compared), a simulation of reflections and crosstalk on a line, a power-network impedance sweep of the board's copper (the rail impedance of `references/pcb-rules/power.md` PWR-49 is simulated from the parts, in the SPICE campaign), and helpers for the fan-out of ball-grid packages. A board that needs them (USB 3, HDMI, PCIe, MIPI, DDR memory, multi-gigabit links, fine-pitch ball-grid chips, RF beyond a simple 50 ohm line) is outside the proven range: say so and continue only as the paragraph on the proven range in `SKILL.md` allows.

**Pictures that no script of this skill makes** (the device sketch of phase 1, the block diagram and power tree of phase 2, the placement sketch and outline preview of phase 8, section views) are drawn by a short script of the project in `src/` (matplotlib, saved as PNG), so that they can be made again when something changes. Boxes and labels are enough. Open each picture before showing it.

**Also not provided:** a tool that draws a section view through a panel connector, and an enclosure fit check. Phase 8 asks for the section as a drawing made with whatever CAD or 2D means the project has. The enclosure fit is checked in the project's own CAD; where that is not possible the designer's check is FAIL "cannot run", it is carried to the mechanical review with the section views, and what the review cannot judge stays UNKNOWN.

## 5. Notes per tool

**KiCad.** Use the command line and the bundled Python; never the graphical program for automated work. `env_check.py` reads the version. The scripts are proven on KiCad 9; on a newer version it reports the difference instead of guessing at a changed file format. Load and save boards only through `scripts/kicad_io.py`. Fill zones in a separate process and re-check the saved file, not the in-memory one.

**ngspice.** Runs from the command line and in parallel; each run needs a private temporary folder. Check convergence before using any number. Maker models are often encrypted for one vendor's simulator: then build a behavioural model from the datasheet, calibrate it on a published measurement, and say so in the results.

**Browser extension.** Use supplier sites at a human pace: one session, seconds between page loads, stop at the first refusal (`references/working-rules.md` section 8). The user signs in; the agent never types a password. After a restart of the user's machine the extension may need to be reconnected by the user. Click by element reference, not by screen coordinates. Never click a download.

**Notifications.** After sending one, confirm delivery where the tool allows it. A silent failure of the channel looks the same as "nothing happened".
