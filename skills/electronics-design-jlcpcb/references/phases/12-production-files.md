# Phase 12: production files

Export, check and freeze exactly the files that will be uploaded, and settle the cost and the shipping plan before any payment.

## Inputs

- Gate 2 approved in `PROJECT_STATE.md` (approved board checksum, release state), or skipped by the user with their words recorded.
- The approved board, `BOARD_DEFINITION.md`, the BOM, the waiver list, `GATE2_SUMMARY.md`; or, for production files the user brought with no board, their Gerber zip, BOM and placement file.
- `references/jlcpcb/capabilities.md`, `assembly.md`, `parts-library.md`, `order-flow.md`, `combined-shipping.md`; the lessons section of any earlier `ORDER_LOG.md`.
- `references/review-briefs/supplier-rules.md`, `templates/ORDERING_CHECKLIST.md`; `templates/ECO_LIST.md` for the user's own files.
- `scripts/fab_package.py`, `scripts/fetch_parts.py`, `scripts/jlc_rotations.py`, `scripts/jlc_parts.py`, `scripts/panel.py`, `scripts/edge_check.py`, `scripts/privacy_scan.py`.
- `references/lessons.md`, section "Phase 12: production files".

## Steps

**Steps 1 to 7 have already run once, before gate 2** (phase 11, step 14b), as a draft on the board that the user then approved, so that the approval came after the supplier-rules review. After the approval, start here: confirm that the board file's checksum equals the approved one. If the draft package was exported from exactly that board, its checksums equal the ones the supplier-rules re-check saw, and `fab_package.py --check` passes (board, `board.toml`, BOM table, library footprints, tools and KiCad version unchanged), steps 1 to 7 are done: go on with step 8. If the board changed after that export (a waiver decision, a change the user asked for at the gate), it goes back through phase 11 step 11 (the difference listed, looked at, and re-reviewed if it touches copper, footprints or silkscreen), steps 1 to 7 again on the new board with the supplier-rules reviewer re-checking the changed files once, and a new gate 2 approval that records the new checksum; then start here again.

**Production files the user brought, with no board** (way of use "order existing files", `references/existing-designs.md`). The same steps, on their files:
- Copy their Gerber zip, BOM and placement file byte for byte into `out/jlc/` and record the checksums under `source:`. Nothing is exported or regenerated, and their files are never edited. A BOM or placement file in another tool's columns is converted on a copy, columns only, with both checksums recorded.
- Steps 1, 2 and 4 do not apply, nor the rotation test of step 6. Rotations cannot be derived without the board: every polarised part is UNKNOWN, and the checklist names what to see for it (the pin-1 or polarity mark on their silkscreen, or their assembly drawing). It is checked in JLCPCB's placement preview (phase 13) and at the placement confirmation (phase 14). A polarised part with neither a mark nor a drawing goes to the user before the order.
- Steps 3 and 5 to 12 run on their files; step 9's freshness gate does not apply (no manifest): the checksums under `source:` stand in for it. Board options they did not state (thickness, copper, finish, colour) take the defaults of phase 8 (steps 9 and 15) as written assumptions they can veto. The supplier-rules review uses the freeze `reviews/frozen/files-r<round>-<first 12 characters of the SHA-256 of the Gerber zip>/` (`files-r0-...` for the first). A visual review from the drawn layers is added: `python -I scripts/review_images.py --gerbers <folder> --out <folder>` draws every Gerber layer and the drill files from the production files alone.
- Every fix goes to the user as a change list (`templates/ECO_LIST.md`), never into their files; the LCSC mapping of a BOM without LCSC numbers too (`references/existing-designs.md` section 3, item 7). On a go that names the changes, they send corrected files or the changes are made on the copy (`references/existing-designs.md` section 5); either way the new files get new checksums and the checks of this phase run again on them.

1. **Export from the approved board only.** Confirm that the board file's checksum equals the one of gate 2, then run `scripts/fab_package.py`: Gerbers of every layer, drill files, the BOM and the placement file in JLCPCB's format, the zip; `scripts/review_images.py` makes the assembly drawing and `scripts/interface_export.py` the 3D model.
   - The files for an order come from the tool that holds the master: for an imported design that was only reviewed, the user's own tool exports them, and the checks that read exports run on those files (`references/existing-designs.md`, section 2b).
2. **Derive every placement rotation from JLCPCB's own footprint** . First fetch JLCPCB's library footprint for each LCSC number with `scripts/fetch_parts.py jlc-footprint` (kept under `vendor/`). Then `scripts/jlc_rotations.py derive` lays each one on ours pin 1 on pin 1 and writes rotation and origin per part with the pad error to `out/jlc/rotations.md` (and `rotations.json`); `jlc_rotations.py test` derives everything again and compares with the placement file.
   - A part with no saved footprint is UNKNOWN, never a guess. A rotation set by hand is declared in `board.toml` (`[rotations.declared.<designator>]`) with its written reason.
   - A fit counts only with two matched pads at different places, no other turn that fits as well on other pins (else UNKNOWN, AMBIGUOUS), a pad error within the part's limit (0.75 x the smaller side of the pads involved, at most 0.6 mm; above it the part is FAIL: the footprints do not fit) and a counterpart for every pad of both footprints. A pad that is right without one is named with its reason under `[rotations.unmatched_pads.<LCSC>]`.
   - A declared part (`[rotations.declared.<REF>]`) is DECLARED, NOT MEASURED: no pad error, its own table, and its preview check is mandatory.
   - Bottom-side parts stay UNKNOWN with candidate angles until their convention is seen in JLCPCB's placement preview for this board: `scripts/fab_package.py --preview` writes `out/jlc_preview/` (PREVIEW ONLY, NOT FOR ORDER); phase 11 step 14b uploads it for the preview only, before the supplier-rules review; then record `[[rotations.bottom_side_confirmed]]` with `bottom_sha256` (from `rotations.md`), `date` and `evidence` (the crop) and export again. A changed bottom side needs a new look; `bottom_side_checked = true` unlocks nothing. `fab_package.py` writes no placement file for the order while a part is UNKNOWN.
   - The re-derive test proves that the placement file matches the derivation, not that the derivation is physically right: the placement preview does that.
   - Human pace: one session, no bursts, stop at the first refusal (`references/working-rules.md` section 8). Saved footprints are reused; a footprint service answers "forbidden" when asked too fast.
   - Never use a generic rotation table: one would have turned every three-pin transistor on a board.
   - Match two-pin polarised parts by their polarity mark (the cathode band), not by pad number: libraries number diode pads differently.
   - Where the two libraries number or anchor pads differently, fit on the pads that cannot be confused, and say so in the table.
   - A part with no library footprint gets a written reason for its rotation and a line in the preview check of the ordering checklist.
3. **Audit the BOM** with `scripts/jlc_parts.py line-audit` (result `out/bom_line_audit.md`; it flags shared lines and every fitted part without an LCSC number and a maker part number) and by reading it. This step audits; it changes no line.
   - The lines were split in phases 3 and 5. A shared line that holds a value that may ever change (set-point resistors, pull-ups, series resistors in data lines, tuning parts) is a finding: after the order it can only be changed or removed as a whole. Splitting it, or any substitute, now needs the user's go and a fix round (each extended line costs a fee: `references/jlcpcb/parts-library.md`). Write why each remaining shared line can never change.
   - Check value-critical resistors once more against the datasheets of every part they touch. After the order it is too late.
   - Unfitted (DNP) parts keep their footprints and are absent from the BOM and the placement file. Hand-fit parts are absent too.
   - Off-board parts have their own file: housings, crimps, cables, screws, and consumables such as thermal tape, each with LCSC number, quantity per board and life-cycle note.
3b. **Check the parts' process notes against the assembler, before the freeze** (phase 3 step 6b; the live page of the day, `references/jlcpcb/assembly.md` section 14), only for the parts where they matter: the assembler's controlled process covers each moisture level and floor life (their assurance, never a home baking recipe); the reflow passes stay within each part's allowed number; a part that does not stand reflow heat is hand-fit; cleaning suits every part; a hidden joint that needs X-ray inspection has it offered and ordered, never assumed included. Write the result into the ordering checklist.
4. **Export the panel,** if there is one, with `scripts/panel.py`; run DRC on it; check that its placement file equals the board's shifted by each copy's offset: `python -I scripts/drc_run.py <panel board> --out out/panel --no-parity`, then `python -I scripts/jlc_rotations.py --project <board folder> --out out/panel --bom <panel BOM> test <panel board> --cpl <panel placement file>` (the options stand before the word `test`; `--project` gives the footprint folder `vendor/jlc_fp`), then the panel's package `python -I scripts/fab_package.py --project <board folder> --out out/panel --name <name>-panel --bom out/panel/<name>-panel-bom.csv out/panel/board/<name>-panel.kicad_pcb` (Gerbers in `out/panel/jlc/gerbers/`) and `scripts/edge_check.py --project <board folder>`, which measures them, and a render, opened.
5. **Write the fab notes and the order remark.** Notes: the IPC class wanted, stack-up name and layer order, thickness, copper, finish, controlled-impedance lines if ordered (layer, width, gap, target; a width no other track on that layer uses), a drill list with each size once (plated or unplated, finished size, tolerance), mask "as per Gerber" where thin mask webs or covered vias beside pads depend on it (with the openings drawn at their clearance, `references/pcb-rules/dfm-dft.md` DFM-51), via covering as the order form offers it for this layer count on the day (tented or plugged; never untented by accident), parts that overhang an edge on purpose, which edges may carry rails and which must stay free, the order-number mark, panel made by the customer, parts not to be assembled. Remark: two or three plain lines that add only what the form fields cannot say, with no wishes ("if possible") and nothing that contradicts a field. Where a library difference will raise a question (our footprint follows the maker's pitch), answer it there in advance.
5b. **One question to the supplier, only when the rules do not settle a point** (`references/working-rules.md` section 9). The default stays the conservative side and the remark of step 5. When a single open fact decides whether the board can be built or accepted (an unusual stack-up or material, a special slot, a part's process limit, an inspection requirement) and no conservative choice is right whichever way the supplier reads it, ask that one short, specific question before the order, with the user's yes on its text. Record the answer, its scope and date in `ORDER_LOG.md`; ask again when that process changes. Never a list.
6. **Run the checks of phase 10 that read exports** on this final package: `scripts/edge_check.py` on the Gerbers of board and panel, the rotation test, the stock check `scripts/jlc_parts.py bom-check`. The line audit and the stock check save every live answer to `out/jlc_parts_answers.json`; the reviewers read part data only from it, and a number with no saved answer is UNKNOWN to them.
6b. **A board with a programmable part:** its programming and debug access is on the board (connector or pads, reachable with the board mounted), and a minimal bring-up image exists (clock running, one output toggling, the debug port answering) or its owner and date are named. Write both into the ordering checklist and the firmware hand-over. No programmable part: "not applicable".
7. **Run the supplier-rules review** with `references/review-briefs/supplier-rules.md`: an independent agent re-reads JLCPCB's live rule pages into a dated checklist, measures the exported files against it, and reports margins. The dated facts in `references/jlcpcb/` are only its starting index. While it runs it is the only agent on the supplier's site: it reads each rule page once, slowly, saves the text and works from the copy. Fix, export again, and have the same reviewer re-check its findings once on the new files (for the user's own files, through the change list above). The end rule holds (`references/reviews.md` section 6): a `DO NOT ORDER` finding is a blocker, closed or accepted by the user in writing before the order; whatever else is still open after the re-check goes into the ordering checklist as a note for the user.
8. **Scan for private data** with `scripts/privacy_scan.py`: every file of the upload folder, the 3D model, the PDFs. Exporters write the system user name, the host name and home paths into headers. Fix the exporter setting, export again, scan again.
9. **Freeze.** Write the revision and the SHA-256 of each file and of the zip into the state file and the ordering checklist. Store the folder byte for byte: if version control would convert line endings, propose the byte-exact setting for `hardware/` and apply it on the user's go, never silently; then hash the stored copy again. The freshness gate (`scripts/fab_package.py --check`) refuses a package with any output older than the board, any changed input (it names it: board, `board.toml`, BOM table, a library footprint, a tool, the KiCad version) and any preview-only package. A package made before inputs were recorded fails it: export once more.
10. **Estimate the landed cost** in a table: boards, assembly set-up and stencil, fees for extended parts, parts with attrition, shipping, duties and taxes, the total and the cost per board, against the cost target of the requirements where one exists (`references/working-rules.md` section 11); a miss goes to the user before the order, with its drivers. Use the quantity the user stated or the requirements give, otherwise 5 boards with 2 assembled for first samples. Mark every estimate as one, and add the note that the shipping and duty choice at payment can raise the total (by as much as a quarter).
11. **Plan the shipping of all orders together, before the first payment.** List every order of this project: boards, loose parts at LCSC, cables, enclosure parts.
   - Read the combine conditions on the live pages (`references/jlcpcb/combined-shipping.md`), end to end.
   - The destination of the board order is set at its own checkout and cannot be changed afterwards.
   - Each storefront keeps its own address book. Have the user check each one.
   - The order that joins the others is placed last, while the earlier ones are paid and not yet packed.
   - Give every dependency a fallback date: "if the cable quote is not in by `<date>`, the parts ship without it".
   - Explain the plan to the user in three lines and one table: order, ships to, joins which order, fallback date.
12. **Fill `ORDERING_CHECKLIST.md`:** board options with their exact values, assembly options, what to see in the placement preview for every polarised part, and the checks before paying. Re-read the option names on the live page that day. Fill its evidence status. Nothing is ordered until every box is ticked or answered "not applicable: `<reason>`".

## Questions for the user

Ask only when more than one order exists. The quantity (unless the user stated it), the shipping method and the address are asked in phase 13.

- Shall `<the loose parts and cables>` travel in one parcel with the boards?
  - Suggested: `<yes, joined at the last order | no, ship the boards alone>`.
  - Why: `<one parcel saves about <amount> and one customs handling | joining would hold the boards until <date>>`.

## Checks before leaving this phase

- [ ] The supplier-rules review ran before gate 2, and the package is the one its re-check saw. Evidence: the checksums in `reviews/VERIFY_<round>_SR.md` against `out/jlc/manifest.json` (the user's own files: against `source:`).
- [ ] The package was built from the board approved at gate 2, or is the user's own files unchanged. Evidence: the checksum in the package report against `gate2` in the state file, or the copies' checksums against `source:`.
- [ ] The rotation table has a row per placed part with source footprint, pads used for the fit, pad error and rotation; the re-derive test passed. For the user's own files: every polarised part is UNKNOWN with what to see in the preview. Evidence: `out/jlc/rotations.md`, the test result, the preview section of the checklist.
- [ ] Each shared BOM line states why its values can never change; every fitted part has an LCSC number and a maker part number; DNP and hand-fit parts are absent from BOM and placement file; the off-board parts file exists. Evidence: `out/bom_line_audit.md`, a search of both files for those designators.
- [ ] The edge check passed on the final Gerbers of board and panel. Evidence: `out/edge_check.md` with the measured minimum.
- [ ] The parts' process limits were checked against the assembler, and a programmable part has its programming access and a bring-up image or its owner and date. Evidence: those boxes of `ORDERING_CHECKLIST.md`.
- [ ] A question to the supplier, if any, was a single one sent with the user's yes, and its answer, scope and date are recorded. Evidence: `ORDER_LOG.md`.
- [ ] The supplier-rules report names the date each page was read; its findings were re-checked once, no blocker is open unless the user accepted it in writing, and what else is open is a note in the ordering checklist. Evidence: `reviews/SR_SUPPLIER_RULES_FINDINGS.md` and its closure file `reviews/VERIFY_<round>_SR.md`.
- [ ] The privacy scan reports 0 hits on every file. Evidence: `out/privacy_scan.md`.
- [ ] The stored copy's checksums equal the ones in the state file and the ordering checklist; no output is older than its sources. Evidence: the re-hash of the stored copy, the freshness result.
- [ ] The landed cost table and the shipping plan table exist; the plan gives destination and fallback date per order. Evidence: the cost section, the shipping plan in `ORDER_LOG.md`.
- [ ] `ORDERING_CHECKLIST.md` is complete and dated. Evidence: the file.

## Outputs

- `out/jlc/`: the Gerber and drill zip, the BOM, the placement file, `manifest.json`, `rotations.md`, the fab notes, the off-board parts file; `out/panel/` when there is a panel
- `out/`: `privacy_scan.md`, `edge_check.md`, `bom_line_audit.md`, `BOM_STOCK_CHECK.md` dated, the landed cost table
- `reviews/SR_SUPPLIER_RULES_FINDINGS.md` and its closure file `reviews/VERIFY_<round>_SR.md`
- `ORDERING_CHECKLIST.md`; the shipping plan in `ORDER_LOG.md`
- `PROJECT_STATE.md`: revision, checksums of the frozen upload folder, next action phase 13

## Lessons behind this phase

- Rotations came from a generic community table: many three-pin parts and one electrolytic would have been placed wrong -> step 2 derives each from JLCPCB's own footprint and tests it.
- One diode's library footprint numbers the cathode as pad 2; matching by pad number would have turned it -> step 2 matches by the band.
- One resistor shared a BOM line with others; after the order it could not be changed alone -> phases 3 and 5 give uncertain values their own line; step 3 audits it.
- Exported 3D files can carry the system user name in their headers, and are easily uploaded unread -> step 8 scans every file and fixes the exporter.
- Line-ending conversion in version control changed a reviewed file, so its checksum no longer matched -> step 9 stores byte for byte and hashes again.
- A builder's own checks compared design targets; an independent reader of every rule page measured the exported files and found ten failures -> step 7.
- The condition for combined shipping (the first order must go to the distributor's warehouse) was found after the first checkout, when it could no longer be set -> step 11 plans all orders before the first payment.
- Thermal tape for a heat sink was never on a list; the heat sink stayed off -> step 3 lists consumables as off-board parts.

The full cases are in `references/lessons.md`.
